# Base Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the new Base mode semantics and rename the compressed preset surface from `max` to `optimized`.

**Architecture:** Keep the current two-stage shape for this branch: `convert.ts` still projects BPMN XML into JSON and applies the existing optimized behavior through config flags. Base preset flags must stop doing any compaction, while the old `max` behavior is renamed to `optimized` until the dedicated optimized pipeline branch replaces it.

**Tech Stack:** TypeScript, `bpmn-moddle`, `camunda-bpmn-moddle`, Vitest, `tsx`.

- [ ] **Step 3: Implement Base semantics**

In `src/config.ts`, set Base to:

```ts
optimizations: {
  compactMappings: false,
  compactSameNameMappings: false,
  compactServiceTaskImplementation: false,
  compactTypes: false,
  compactFlowRefs: false,
  compactCallActivity: false,
  compactConditions: false,
  omitIncomingOutgoing: false,
  omitDefinitions: false
}
```

In `src/convert.ts`:

- add `asyncBefore`, `asyncAfter`, and `exclusive` to `EXECUTION_KEY_MAP`;
- only project execution keys that are own moddle properties, so default prototype values such as `asyncAfter: false` and `exclusive: true` are not emitted when absent in BPMN XML;
- remove `documentation` from projected flow elements;
- make `projectExtensions` compact mappings only when `config.optimizations?.compactMappings` is true;
- when compact mappings are false, group typed extension elements as structured objects under their `$type` key.

Create `vitest.config.ts` so the main project test suite excludes `.worktrees/**`:

```ts

    exclude: [...configDefaults.exclude, '**/.worktrees/**']
```
